Integration decisions

The service keeps its current SSE and JSON Lines contracts. Its executor still consumes AIMessageChunk values from graph streams. The Core 1.7.0 change affects direct consumers of the v3 content-block protocol. Applications that use that protocol must concatenate tool-call-delta slices. Use .tool_calls.get() or .output for the complete result.

The model factory passes provider configuration to the selected native model. For an OpenAI-compatible gateway that requires Chat Completions, set use_responses_api=false in its MODEL_CONFIGS entry. For document inputs that need Responses, set use_responses_api=true. The dependency update does not change these explicit settings.

The blueprint supports native Deep Agents permissions, skills, memory sources, and asynchronous subagent definitions. Existing defaults stay unchanged. Asynchronous subagents need an external Agent Protocol service. The toolkit REST service does not provide that protocol. Review resolved filesystem paths when you use symlinks and permission rules. Treat configured skill and memory source paths as trusted input.

FastMCP 4.1 changes server-side security checks and session ownership. Finish pending MultiAuth tasks before you upgrade a separate FastMCP server. For direct ClientCredentialsOAuthProvider or PrivateKeyJWTOAuthProvider use, configure issuer to enable issuer binding. The toolkit’s shared-header client configuration does not use these providers. The toolkit closes protocol sessions after calls and reuses only HTTP pools. It does not keep an idle protocol session for 30 minutes. Use the per-server max_sse_event_size setting for larger HTTP SSE results. Its default preserves the SDK’s 1 MiB limit. See MCP tools. FastMCP 4.2.0a1 is a pre-release. This update excludes it.

Rebuild images and update operating-system and custom certificate stores. Updating certifi does not update those stores. See the FastMCP CA security notice.

langchain-community==0.4.2 remains the latest stable release. The update does not replace the toolkit’s authentication or memory scopes. user_id remains the long-term user scope. thread_id remains the short-term conversation scope.

Checkpoint upgrade operations

Back up the database before this update. Stop active requests before you update SQLite workers. SQLite saver setup adds writes.task_path to databases from version 3.1.1. The migration keeps existing rows. Do not mix old and new SQLite saver versions during this change. The regression fixture uses a database from the released 3.1.1 saver. It verifies a pending interrupt and a completed parallel branch after upgrade.

The PostgreSQL saver migration list is unchanged from 3.1.2 to 3.2.0. The toolkit still runs saver setup under its schema lock. Run checkpoint migrations and resume checks before you replace all workers.

Store namespace labels cannot contain periods, NUL bytes, or empty strings. Validation now also covers reads, searches, and direct batch operations. Encode user identifiers before you use them as namespace labels. The toolkit’s scoped checkpoint keys already use safe labels. Keep long-term user memory separate from conversation checkpoints.

The new PostgreSQL aprune default is strategy="keep_latest". It keeps current state and pending interrupts for supported threads. It refuses DeltaChannel threads because they need older writes. Deep Agents uses these channels. The toolkit does not run this maintenance method automatically. Do not replace checkpoint deletion with pruning for Deep Agents threads. External media blobs still need their own retention policy.

LangGraph 1.2.18 takes a delta snapshot after 100 updates by default. This can reduce restore time and increase database storage. Set snapshot_frequency=1000 on a custom DeltaChannel to keep its old interval. An explicit interval on an upstream channel still takes precedence.

Typed interrupts use native schema validation. The toolkit returns response_schema in live and recovered interrupt records. Send answers as input.resume values keyed by interrupt ID. The order of parallel interrupt records can differ between live and saved responses. Use IDs to match questions and answers. A Python response type enables native validation. A JSON Schema dictionary describes the response without enabling that validation.

Optional Studio server and runtime

The studio extra installs langgraph-cli[inmem]. It now selects langgraph-api==0.16.7 and langgraph-runtime-inmem==0.36.7. The previous versions were 0.10.3 and 0.30.3. These packages run the separate Studio development server. They do not replace the toolkit’s FastAPI server, checkpointer, or request queue.

The official Agent Server changelog documents the API release families. The summaries below include fixes added to each family.

  • 0.11: Add delta-aware pruning and Prometheus metrics. Correct durable interrupt resume and conditional-thread authorization. Metrics names and units change.

  • 0.12: Add search cost limits and gRPC stores. Fix store authorization filters, resume races, subgraph events, and namespace matching.

  • 0.13: Support Python 3.14 and A2A file output. Preserve cancellation across worker failures. Fix thread authorization and queue port conflicts.

  • 0.14: Support custom encryption with gRPC checkpoints. Fix scheduler duplication, lock contention, delta restoration, auth checks, and cancellation.

  • 0.15: Add A2UI and task-only A2A history. Fix false interrupt results, HTTPS webhooks, gRPC replay, startup failures, and tracing dependencies.

  • 0.16: Add typed interrupts, storage diagnostics, and dependency health details. Preserve pending questions and retry killed in-memory runs after restart. Correct delta history and transient-error streaming. Version 0.16.7 fixes factory-graph state operations with gRPC checkpoints.

The runtime 0.36.7 metadata has no separate patch changelog. Its review uses the API changelog and published requirements. It does not establish a patch-by-patch runtime change list. The selected API requires grpcio-tools==1.81.1, compatible gRPC 1.81 packages, and protobuf>=6.32.1,<7.0.0. It also requires anyio>=4.14.2 and starlette>=1.3.1. The lockfile resolves these requirements together. Do not independently pin the runtime to an incompatible API family.

The verification covers dependency resolution, CLI help, and SDK contracts. It does not verify a running Studio server or a remote Agent Server deployment. Test graph loading, persisted local state, and pending questions in Studio before you replace an existing Studio environment. The 0.17 API family remains a release candidate at this review date. Its optional run-drain handoff is excluded from this stable update.
